# Maintaining the history atlas

This is the working manual for Wei and future assistants. Read it before adding cards, notes, pictures, or timeline labels. Paths below are relative to this directory unless stated otherwise. Last checked: 5 September 2026.

## Start here

1. Search existing cards before adding a subject. Expand an existing card when it already covers the event; retain its ID so links, images and source mappings survive.
2. Choose the smallest change: a reading-note revision, a new searchable card, or a visible timeline event. A new card does not automatically need a printed label.
3. Research the account, write the card, add Simplified Chinese and pinyin, and supply a credited image.
4. Regenerate the reading export, run the relevant checks, and inspect the actual card on desktop and phone.
5. Report what changed and whether it is local or published. Editing this folder does not update GitHub Pages.

The site is a static application. There is no package installation or application build required to serve it. Node is used for export and tests; browser tests also require Playwright and a browser.

## Which file should I change?

| Task | Source to edit |
| --- | --- |
| Expand an existing card or add a historical note | Its existing entry in an era research pack, usually `revisions[cardId]` |
| Add an event | The appropriate era pack's `events` collection; follow that file's helper convention |
| Add or correct a Chinese reading | The pack's `pinyin` map or `pinyin_data.js` |
| Add or replace an illustration | `image_data.js`, keyed by the exact card ID |
| Change major period bands or overlapping states | `history_data.js`; this requires extra chronology and layout checks |
| Change label placement or interactions | `app.js` |
| Change the time scale and ribbon path | `geometry.js` |
| Change card presentation | `styles.css` and the rendering code in `app.js` |
| Update the downloadable reading data | Run `build_expanded.js`; do not hand-edit its output |

Era packs are `early_research.js`, `medieval_research.js`, `medieval_culture.js`, `late_imperial_research.js`, and `modern_research.js`. `tang_data.js` contains the earlier Tang expansion. `chart_research.js` contains additions and clarifications from Wei's reference chart, plus its coverage checklist. `research_revisions.js` contains earlier revisions. Later packs can override earlier fields, so search the card ID across all files before editing.

`data/china_history_v10.json` remains an archived source edition. The active catalogue now comes from `data/china_history_v11.json`, the audited Excel export. `catalog_data.js` is generated by `build_catalog.js`; do not hand-edit it. The 111 original identifiers remain. `catalog_adapter.js` reconciles those records with curated subjects; preserve its source-ID mappings. `data/date_audit.json` records the 5 September review of all 205 card dates. The final date revisions in `chart_research.js` apply after earlier research packs, so check them when changing a date.

## New card recipe

Use the helper already present in the chosen file. Helpers differ between packs; read its arguments rather than copying a call from another pack. The resulting record has this shape (illustrative placeholders, not publishable research):

```js
{
  id: 'unique-stable-event-id',
  name: 'English event title',
  nameZh: '简体中文名称',
  han: '字',
  start: 600,
  end: 601,
  parent: 'sui',
  related: ['sui'],
  color: '#987950',
  category: 'event',
  ribbon: true,
  label: false,
  description: 'A factual introduction explaining what happened and when.',
  sections: [
    {title: 'A specific historical question', text: 'Evidence and explanation.'},
    {title: 'Consequences and limits', text: 'A second substantive analysis.'}
  ],
  note: 'Dating conventions, uncertainty, or limits of the evidence.',
  source: 'https://example.org/replace-with-verified-source',
  sources: ['https://example.org/replace-with-verified-source'],
  sourceLabels: {
    'https://example.org/replace-with-verified-source': 'Institution · Specific work'
  }
}
```

Use an existing valid parent ID, not a display name. Every related ID must resolve to a card. IDs are permanent identifiers: never rename one merely to improve the English title. Search both English and Chinese names to avoid duplicating a catalogue subject under a new ID.

Register tone-marked pinyin for both the full `nameZh` and the banner `han` in the pack's pinyin map or `pinyin_data.js`. A record-level pinyin field alone is insufficient for the current export and validation. Check historical names and polyphonic characters manually. Keep Chinese text Simplified, including captions and notes. The full-name reading and the standalone banner reading can differ by context.

Use negative numbers for BCE, positive numbers for CE, and never year zero. A single-year event has equal start and end. Do not invent exact dates for legendary people or uncertain textual formation: explain the convention in `note` and the introduction.

For an ordinary new event, `ribbon: true` requests a marker on the overview. All events now use dots with hover/focus previews; the renderer ignores legacy event label flags. Period and state names remain visible. Keep `label: false` on new event records for clarity. It remains selectable through its dot and searchable in Browse all. Omit `ribbon` for a new reading-only entry and confirm its resulting visibility in the browser. Do not turn every new card into a named timeline label.

### Data-loading pitfalls

- The adapter appends additions without deduplicating IDs. Check uniqueness before saving. Never set `ribbon: true` on an existing core event simply to make it visible: core events are already included and can be drawn twice.
- Additions receive adapter defaults for `kind`, `catalogOnly`, `importance`, and `evidence`; values supplied directly on the addition for those fields can be overwritten. Use a deliberate revision if one of those defaults must change, then inspect the assembled result.
- Revisions update reading-card copies. Core chart shapes still use `history_data.js` objects. Changing a core card's date or label through a revision alone may leave its timeline position or label unchanged.
- Image and revision keys use final card IDs, which can be names such as `republic` or catalogue-derived IDs such as `catalog-E_MOD_MAY4`. Use `sourceMap` to resolve a workbook ID rather than guessing.

## Adding notes to an existing card

Use a revision keyed by the existing ID. `description` supplies the introduction, `sections` holds titled analysis, and `note` explains chronology or evidence limits. There is no separate persistent personal-notebook feature: these fields are shared site content.

The revision merge preserves source URLs and combines source labels. Ordinary fields are replaced by the later revision. In particular, a new `sections` array replaces the earlier array; it does not append automatically. To add an analytical section, preserve the existing sections in the intended final array. Do not overwrite an established essay with a short clarification.

Browser composition currently applies Tang revisions, `research_revisions.js`, then the era packs in the order listed in `app.js`, ending with `chart_research.js`. The export must compose the same material in the same order.

## Editorial standard

The active reading edition is for curious Mandarin learners. Read [the audience guide](audience-guide.md). Apply reader-facing rewrites through `beginner_early.js`, `beginner_middle.js`, or `beginner_late.js`, then compose them with `beginner_edition.js` after the research packs in both browser and export. Preserve audited dates, sources, Chinese readings, images, and qualifications. Scholar attribution belongs in sources unless essential to a disputed account. The user-approved removal of `taiwan-democratization` is applied to cards, events, and related links; its archived research remains. The ROC in Taiwan card and all 111 workbook subjects remain available.

Each card needs a useful factual introduction and at least two substantive analytical sections. Explain mechanisms: who controlled money, soldiers, labour, institutions or knowledge; what choices were available; and how consequences differed between groups. Avoid generic claims that every event “changed China forever.” Distinguish established facts, scholarly interpretation, and disputed or traditional accounts.

Read sources that support the actual claims. Prefer museum collection records, scholarly reference works, primary texts with context, and specialist scholarship. A publisher abstract is not evidence that the full chapter was read. Record blocked or inaccessible sources honestly. Never invent quotations, citations, image permissions, or precise statistics. A reference chart is a coverage prompt, not unquestionable chronology.

## Illustrations

Add `HISTORY_IMAGES[cardId]` in `image_data.js`. Required fields are:

- `src`: the actual image URL, not an HTML collection page.
- `width`, `height`: positive image dimensions.
- `alt`: a concise visual description.
- `caption`: what the object depicts, its date, and its relationship to the event.
- `credit`, `source`: creator/institution and the individual source page.
- `license`, `licenseUrl`: verified reuse terms and their supporting link.

Every card currently has an illustration. Preserve that standard. A relevant manuscript, artifact, map or painting is often better than an unrelated photograph. Clearly identify later depictions and contextual images; do not imply that a modern reconstruction is contemporary evidence. Reusing an appropriate image is acceptable with an individual, accurate caption. Check both the image URL and its source page, then inspect the rendered image on the card and in Browse all. Automated metadata checks cannot establish historical relevance or image rights.

## If adding a new research file

Prefer an existing era pack for a small addition. A new pack requires all of these registrations:

1. Export it using the existing browser-global and CommonJS pattern.
2. Load its script in `index.html` before `app.js`.
3. Include it in `app.js`'s research-pack composition.
4. Include it in `build_expanded.js` in matching order.
5. Update test compositions that enumerate research packs, especially `encyclopedia.test.js` and applicable expansion tests.
6. Include it when publishing the static site.

Missing one registration can produce a card that exists in the browser but not the JSON, or vice versa. Do not bypass a failing equality test.

## Layout lessons from this project

- About is one reading column aligned to the main page gutter, beneath a divider spanning the page content width. Keep its wording intact during layout-only work. Its minimum height lets the header link place the section near the top of the viewport. Verify the whole landing view and footer, not only a cropped screenshot of the text.

- The compact masthead contains the only search field. Typing opens the collection; Enter or Down Arrow focuses its first result. Escape in the field closes the collection without clearing the query. Browse all clears active search/category filters and shows every card; clicking it again on an unfiltered collection closes it.
- Preserve the nine researched Chinese dynastic navigation groups and their explicit `itemId` destinations. The strip scrolls horizontally and supports keyboard focus on narrow screens. Layer controls stay beside it on desktop and below it on phones. Do not restore the superseded five generic era headings.
- Keep the large promotional hero removed. The small date range and reading card begin immediately below navigation. `header.test.js` checks header search, Browse all, desktop alignment, and phone access.

- Time is proportional to distance along both straights and turns. Never move an event to a different year just to improve spacing.
- Xia now starts at x=12 inside the chart. The extra first-row length is included once in total path length and row starts. Do not restore the old shared left inset or change only the visible path without updating the date mapping.
- Keep labels near their historical row. Earlier free-space placement put Jurchen Jin beside the People's Republic, giving a false chronological impression.
- Prefer short, direct connectors and nearby open space. Sui reunification now uses the space to the right at wide widths. Do not hard-code that direction for every screen: the snake changes row arrangement with width.
- Labels avoid other labels, existing connectors, named anchors, and every visible concurrent-state line. State labels must remain on their own side of the ribbon with a connector no longer than 85 chart units; if no clear placement exists, the state line remains interactive without a printed label. Crossing connectors are omitted. A remaining tradeoff is that crowded displaced dots or labels can lose their connector; inspect their relationship to the date rather than judging only visual neatness.
- `timelineInspection` exposes geometry, labels, markers, leaders and dot leaders for browser checks. Existing crossing tests check proper segment crossings, not every possible endpoint or corner touch.
- Preserve keyboard access when a printed label cannot fit. Clicking a ribbon, state line or event dot must still open the correct card.
- Selected or hovered event text uses red intentionally. It is an interaction state, not a special historical category.
- The Three Kingdoms, Jin, and Northern and Southern Dynasties route uses shortened display intervals alongside overlapping state lines. Reading cards must show canonical full dates. Do not replace Three Kingdoms, Jin and Northern/Southern Dynasties with one division band again.
- The Qing card distinguishes the 1636 declaration from taking Beijing in 1644. The main Republic of China card and ribbon cover the mainland period, 1912–1949. The separate Taiwan card explains the ROC government's continuation. The 2026 endpoint on ongoing entries is the chart horizon. Retain these distinctions when changing labels.

## Local preview and verification

From this directory, serve with:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Then open `http://127.0.0.1:8765/`. If a server is already running from the repository root, use its existing `/history-of-china/snake-timeline/` URL instead; do not start a second server on the same port.

From this directory:

```sh
node build_expanded.js
node --test *.test.js
```

Browser tests require the local server. When serving this directory itself, set `PREVIEW_URL=http://127.0.0.1:8765/`; their default URL assumes the repository-root server. Optional settings are `PLAYWRIGHT_MODULE`, `CHROME_PATH`, and `SCREENSHOT_DIR`. These are machine-specific paths, not dependencies to commit.

For a content addition, check unique IDs, original source mappings, valid dates and relationships, both Chinese readings, analysis, images, and exact browser/export equality. Some tests describe earlier 140/183-card stages or assert fixed counts. Determine whether an assertion protects a historical baseline or the current total before changing it. Never weaken preservation checks just to accept new content.

For layout changes, also inspect wide desktop and narrow phone views, Sui, Jurchen Jin, dense late-Qing/modern events, keyboard selection, mobile close/Escape, and horizontal overflow. The spacing test covers eleven widths from 320 to 2164 pixels. Use a fresh page and move the pointer off the chart before screenshots; hover/focus tooltips can obscure the layout being assessed.
